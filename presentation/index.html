Query Processing

Query Parsing & Execution Modes

Automatic syntax classification and efficient candidate document retrieval.

🎯 Advanced Query Syntax

  • Phrase Search ("ogre bride"): Validates that terms occur sequentially adjacent (pos[t2] = pos[t1] + 1).
  • Prefix Search (ogr*): Uses BTreeMap::range() to expand vocabulary without full scans.
  • Fuzzy Search (ogr~1): Evaluates dynamic programming Levenshtein edit distance against index terms.
  • Boolean Search: Standard multi-term AND / OR scoring.

📊 Okapi BM25 Ranking Formula

Combines inverse document frequency with saturated term frequencies and document length penalties:

IDF(q) = ln(TotalDocs / DocFreq)

Score = IDF * (tf * (k1 + 1)) / 
        (tf + k1 * (1 - b + b * (dl / avgdl)))

• k1 = 1.2 (saturation parameter)
• b = 0.75 (length normalization penalty)

Persistence Subsystem

Custom Binary Segment Format (MNSE v1)

Immutable, compact binary file layout modeled after Apache Lucene.

1. Header

  • Magic: MNSE (4 bytes)
  • Version: 1u32
  • Number of Terms & Docs
  • Total Document Length
  • Section Byte Offsets

2. Term Dict

  • Lexicographically sorted
  • Term length & UTF-8 bytes
  • Postings byte offset
  • Postings section length

3. Postings

  • Postings count per term
  • String DocId length & bytes
  • Term frequency (u32)
  • Array of 0-based positions

4. Doc Store

  • DocId length & bytes
  • Doc length (token count)
  • Length-prefixed Title bytes
  • Length-prefixed Body bytes
Performance & Phase 6

Memory-Mapped I/O (mmap)

Eliminating userspace heap copying with kernel-level zero-copy page caching.

⚡ Why Memory-Mapped I/O?

  • Zero-Copy: File pages are mapped directly into process virtual address space. Deserialization reads slices from &[u8] without heap buffer copies.
  • Page Cache Optimization: Frequently searched segments remain cached by the OS kernel automatically.
  • Memory Pressure Safety: The OS kernel dynamically evicts clean segment pages under memory pressure and faults them back on demand.

📈 Criterion Benchmarks

  • index_1k_docs: ~1,000 docs bulk indexed in under 25 ms.
  • search_single_term: Sub-microsecond term lookup & BM25 ranking.
  • search_phrase: Positional adjacency verification in < 50 µs.
  • search_prefix & search_fuzzy: Microsecond range and distance evaluation.
Phase 7: Multi-Index

Multi-Index Architecture & Concurrency

Independent partition isolation with lock-free parallel querying.

🗂️ Isolated Index Directories

data/
└── indexes/
    ├── default/
    │   ├── segments/
    │   └── wal/wal.log
    ├── books/
    │   ├── segments/
    │   └── wal/wal.log
    └── movies/
        ├── segments/
        └── wal/wal.log

Writes to books do not block or contend with reads or writes to movies.

🔒 Fine-Grained RwLock Model

  • Short Read Locks: Multiple parallel queries acquire read locks simultaneously to traverse immutable segments without blocking.
  • Isolated Write Locks: Document ingestion and flushes only hold brief write locks on the specific index being modified.
  • REST API: Fully namespaced routes under /indexes/{name}/... alongside root default routes.
Operations & Tooling

Command-Line Interface (Clap CLI)

Complete terminal operations for indexing, searching, monitoring, and compaction.

🛠️ Available CLI Subcommands

  • mini-es serve [--port 3000]: Starts the async HTTP API server.
  • mini-es index --file docs.jsonl --index books: Bulk ingest from JSON/JSONL.
  • mini-es search "ogre bride" --index books: Execute queries from terminal.
  • mini-es stats --index books: Print document counts and segment statistics.
  • mini-es compact --index books: Force-merge all segments into one.

⚙️ Declarative TOML Config (config.toml)

[server]
host = "0.0.0.0"
port = 3000

[index]
data_dir = "data"
flush_threshold = 1000
merge_max_segments = 10
default_result_limit = 10

[scoring]
bm25_k1 = 1.2
bm25_b = 0.75
